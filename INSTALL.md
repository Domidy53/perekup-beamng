# Установка и проверка PEREKUP v0.0.1

## Сборка ZIP

Из корня репозитория выполните:

```powershell
python tools/build_mod.py
```

Готовый мод появится в `dist/perekup-v0.0.1.zip`. Архив содержит только папки `lua/`, `scripts/` и `ui/`; автомобили и другие ресурсы BeamNG или сторонних авторов в него не входят.

После push или PR тот же install ZIP загружается в GitHub Actions как отдельный файл `perekup-v0.0.1.zip`. Откройте успешный запуск **Automated tests**, скачайте artifact и положите полученный ZIP прямо в `mods`; контрольная сумма выводится в логе и summary запуска.

## Установка в BeamNG.drive

1. Скопируйте ZIP в папку `mods` активной пользовательской папки BeamNG.drive. Обычно активная папка показывается в Launcher → Manage User Folder.
2. Включите PEREKUP в Mods Manager и перезапустите игру, если интерфейс или Lua-расширение ещё не появились.
3. Загрузите **Free Roam → East Coast USA**.
4. Откройте меню `Esc` → **UI Apps**, добавьте **PEREKUP Career**. Если приложения нет в списке, закройте и заново откройте выбор приложений; затем проверьте, что архив включён и внутри ZIP сразу видны `lua/`, `scripts/`, `ui/`.
5. Для новой карьеры выберите одну из трёх доступных конфигураций разных машин. Каталог моделей и конфигураций берётся из установленной игры и активных модов; если вариантов меньше трёх, будут показаны доступные.

## Проверка игрового цикла на актуальной BeamNG.drive

1. На стационарном ПК сделайте резервную копию тестовой пользовательской папки BeamNG. Установите собранный ZIP, откройте Free Roam → East Coast USA и начните отдельную тестовую карьеру. Проверьте стартовые **$500**, появление выбранной машины и отсутствие второго объекта при повторной команде вывода.
2. Продайте стартовую машину и проверьте, что остаётся объявление, доступное с резервом расчётного ремонта. Купленная машина должна получить отдельный карьерный ID и появляться только после **Вывести в мир**.
3. Перед возвратом измените детали, переменные конфигурации и окраску через Parts Selector, затем нанесите заметное физическое повреждение. Выйдите из машины, верните её в гараж и дождитесь подтверждения checkpoint. Повторно выведите запись и сравните детали, окраску и физическое состояние.
4. Проверьте физический reset. До подтверждённого post-reset файла баланс не меняется; после подтверждения списывается ровно одна стоимость ремонта. Повторный клик и повторное подтверждение не должны списать её ещё раз.
5. Верните отремонтированную машину, выставьте и продайте. Проверьте баланс и историю, затем перейдите к следующему дню.
6. Полностью перезапустите BeamNG, продолжите карьеру и выведите сохранённую машину. Проверьте восстановление конфигурации и физического checkpoint. Любой объект, который остался в Free Roam без связи с PEREKUP, должен остаться нетронутым; удалите его вручную перед новым выводом, чтобы не получить два видимых экземпляра.
7. На копии тестовой карьеры проверьте восстановление незавершённых операций: перезапустите игру, пока приложение показывает ожидание сохранения или ремонта. Старый числовой ID не должен получать команды. Валидный файл может завершить операцию; если исход reset неизвестен или checkpoint несовместим, баланс не списывается до безопасного восстановления машины.
8. Повторите проверку с автомобилем стороннего мода и после обновления BeamNG. Совместимость с каждой такой машиной проверяется отдельно; при несовпадении файла мод должен отказать в восстановлении и сохранить карьерную запись.

## Диагностика после первого запуска

Если появилась ошибка или действие зависло, нажмите кнопку со стрелкой вниз в заголовке PEREKUP. Она сохранит `settings/perekup_diagnostics.json` в активной пользовательской папке игры. В отчёт входят версия мода, схема и краткая сводка карьеры, доступность API и последние коды событий; игровые object ID, имена автомобилей, конфигурации и содержимое файлов сохранения туда не добавляются.

Передайте Codex этот JSON и только относящиеся к проблеме строки из `beamng.log` активной пользовательской папки. Найти эту папку можно через Launcher → Manage User Folder → Open in Explorer. В логе могут встречаться данные других модов и пути к папкам пользователя — проверьте и при необходимости удалите такие строки перед отправкой. Если проблема касается карьеры или checkpoint, дополнительно приложите `settings/perekup_career.json`, его `.bak` и только относящийся к машине файл из `settings/perekup_vehicle_states/`; они могут содержать названия конфигураций и игровых объектов.

Сохранение карьеры находится в `settings/perekup_career.json`, резервная копия — `settings/perekup_career.json.bak`. Физические состояния пишутся в `settings/perekup_vehicle_states/` активной пользовательской папки BeamNG. Эти файлы создаются самой игрой вне ZIP.

## API и проверка совместимости

UI App, Free Roam UI Apps, модуль Lua extension и обмен между UI и Game Engine Lua собраны по [официальным инструкциям BeamNG по UI Apps](https://documentation.beamng.com/modding/ui/app_creation/), [Lua extensions](https://documentation.beamng.com/modding/programming/extensions/) и [между Lua/UI VM](https://documentation.beamng.com/modding/programming/virtualmachines/). ZIP использует корневые папки мода из [официального правила упаковки](https://documentation.beamng.com/modding/mod-support/mod_packing/).

Каталог конфигураций подключён через внутренние GE-функции `core_vehicles.getModelList(true)` и `core_vehicles.getConfigList(true)`, приведённые в [ответе команды BeamNG на форуме моддеров](https://www.beamng.com/threads/how-do-i-spawn-a-random-vehicle-using-lua.72847/). Физический объект создаётся отдельным адаптером через `core_vehicles.spawnNewVehicle`; его форма сверена с [открытым примером RLS Career Overhaul](https://github.com/RLS-Modding/rls_career_overhaul/blob/4db9ea9b19d02202c033c9d494d4020b01ab87a0/lua/ge/extensions/overhaul/career/business/fleet/garage.lua). Подробный официальный контракт этих игровых функций не опубликован, поэтому каждый вызов проверяется на наличие и успешный результат. Финальную совместимость нужно подтвердить на целевом ПК.

Экономика использует `Value`, мощность, массу и класс конфигурации, если они доступны. В [официальной справке по конфигурациям](https://documentation.beamng.com/modding/vehicle/tutorials/configs/) `Value` назван ценой автомобиля, но указан как поле, используемое для сортировки конфигураций в селекторе; поэтому это только базовый игровой ориентир, не подтверждённая рыночная или MSRP-цена. Остальные цены и состояние — расчёты карьеры, ограниченные разумными диапазонами. В правом верхнем углу приложения можно выбрать русский или английский; выбор хранится в настройках UI App.

Ремонт выполняется в Lua VM автомобиля: сначала создаётся и проверяется исходный checkpoint, затем запрашивается `requestReset(RESET_PHYSICS)`, после штатного `onReset` записывается post-reset файл. Деньги списываются только после проверки этого файла и сохранения карьеры. Названия хуков `onReset` и `updateGFX(dt)` соответствуют [официальной документации по vehicle-specific Lua](https://documentation.beamng.com/modding/input/vehicle-specific-bindings/); обмен кодом между VM использует документированную очередь [`obj:queueGameEngineLua`](https://documentation.beamng.com/modding/programming/virtualmachines/).

Физический файл основан на внутреннем BeamNG-модуле `beamstate.save/load`, который сохранён в открытом примере [Beam Legal Racing](https://github.com/r3eckon/BNG-BeamLegalRacing/blob/a92984556e21c1272ac27297eccf60ff1b2eac3c/Source/lua/vehicle/beamstate.lua). В формате `v2` этот модуль записывает узлы, балки, гидравлику и сериализованное состояние Lua-пакетов; при загрузке проверяет формат, каталог автомобиля, число узлов и балок, а затем вызывает `commitLoad()`. В исходнике есть пометка, что цвет не сохраняется, поэтому PEREKUP отдельно сохраняет `.pc`-поля `parts`, `vars`, `paints` и `licenseName`; официальное описание `.pc` подтверждает эти поля и их назначение в [документации конфигураций BeamNG](https://documentation.beamng.com/modding/vehicle/tutorials/configs/).

`beamstate.save/load`, `core_vehicle_manager.getVehicleData`, `core_vehicles.spawnNewVehicle`, `obj:getID`, `obj:setName`/`obj:getName`, поиск `scenetree.findObject`, `obj:delete`, `be:getPlayerVehicleID`, `gameplay_walk.setWalkingMode`, `obj:requestReset`, `resetBrokenFlexMesh`, хук `onVehicleDestroyed`, `FS:fileExists` и `FS:directoryCreate` — игровые вызовы, для которых нет опубликованного стабильного контракта для модов. `setName`, `getName` и поиск по имени показаны в [официальной документации BeamNG по дереву объектов](https://documentation.beamng.com/world_editor/api_reference/undo_system/); это не гарантирует совместимость именно с объектами Vehicle в любой версии. Формы внутренних вызовов также сверены с [открытым примером гаража RLS Career Overhaul](https://github.com/RLS-Modding/rls_career_overhaul/blob/4db9ea9b19d02202c033c9d494d4020b01ab87a0/lua/ge/extensions/overhaul/career/business/fleet/garage.lua); пример не гарантирует их для каждой версии и машины. Команды к vehicle Lua передаются через документированную очередь `obj:queueLuaCommand`. Все операции ограждены проверками и завершаются отказом при несовпадении данных. Официального стабильного API для сериализации целого физического автомобиля не найдено.

## Границы этой сборки

Карьерные данные сохраняются отдельно от физических файлов. Реализация пытается подтвердить запись конфигурации и Beamstate checkpoint до удаления мирового объекта; при выводе создаётся новый объект, применяется сохранённая конфигурация, затем загружается совместимый checkpoint. Это отдельный путь сериализации, а не обычный повторный спавн под видом физического сохранения. Поскольку `beamstate` — внутренний API, фактическое восстановление физики нужно проверить на актуальной BeamNG.drive; локальные тесты проверяют только формат, проверки совместимости и последовательность операций. Сторонние Lua-модули могут хранить состояние вне сериализуемых пакетов, поэтому полное восстановление для них не гарантируется. Если checkpoint отсутствует или не проходит проверки, запись владения сохраняется, а восстановление отклоняется.

Постоянный идентификатор автомобиля — `vehicle.id` в карьере. Числовой BeamNG object ID и runtime-токен живут только в памяти сессии; при перезагрузке GE Lua сохраняется лишь счётчик поколения, без ID и связей. Схема сохранения 3 удаляет старые object ID из pending-операций. Документация не определяет, возвращают ли повторные поиски один и тот же Lua userdata, поэтому `rawequal()` не используется. После собственного spawn объект получает уникальное временное имя; повторный поиск сверяет имя и текущий числовой ID. Это допускает разные Lua-обёртки для одного SceneObject. Если `setName`, `getName` или `scenetree.findObject` не подтверждают совпадение, PEREKUP отказывается управлять объектом. После перезапуска старый ID и временное имя не используются для сохранения, ремонта или удаления. Если pending-ремонт уже мог выполнить reset, но post-reset файл отсутствует, операция остаётся без списания и ждёт вывода машины из гаража с восстановлением исходного checkpoint. Если после перезапуска в Free Roam остался несвязанный объект, мод его не трогает; перед повторным выводом карьерной машины уберите такой объект вручную, чтобы избежать двух видимых экземпляров.

Процент состояния и стоимость на рынке остаются оценками карьеры: подтверждённый публичный Lua API чтения реального износа или повреждения не используется. Reset сбрасывает физику целиком, не чинит детали. Совместимость `beamstate`, смены игрового ID, конфигураций сторонних машин и повторного запуска необходимо подтвердить на отдельном стационарном ПК с актуальной BeamNG.drive. Мод не считается полностью играбельным до этой проверки. Карта автоматически не запускается: сначала откройте East Coast USA через Free Roam, затем добавьте UI App.

## Автоматические проверки

```powershell
python -m pip install -r requirements-test.txt
python tools/run_tests.py
```

Lua-тесты запускают бизнес-логику и имитацию границ игровых объектов в Lua 5.1 через Lupa. Они проверяют каталог, экономику и ремонтный резерв при старте с $500, физическую сериализацию/совместимое восстановление, повторное использование ID чужой машиной после перезапуска, устаревшие callback, исчезновение объекта, повторные команды, двойные списания, отсутствующие и несовместимые физические файлы, миграцию сохранения и ZIP. GitHub Actions выполняет тот же набор при push в рабочую ветку и для pull request. Эти статические тесты не запускают BeamNG и не заменяют ручную проверку на целевой игре.
